❓ 面试点：为什么自审要强制只读 + fail-closed？
答：自审是「用自己的标准复查自己的产物」，允许写会用新写掩盖旧错；fail-closed 是宁可多审，不放行「看起来像通过」的坏结果。

03调度与并发

TeamScheduler 决策逻辑、并行策略、worktree 隔离与 AgentPool 租借。

nextWave 四步决策
步方法细节
① 依赖就绪getExecutableSteps :56DependencyGraph.of()，就绪=「依赖 COMPLETED|SKIPPED」；FAILED 阻断下游
② 指纹去重collapseExecutableGroups :76按 stepFingerprint :146 分组，leader 执行、duplicate 复制结果（propagateDuplicateResult :726）
③ 读写分区—读步骤与写步骤拆成不同 wave
④ 串行判定mutatingSerialReasons :110写域为空或重叠（WriteScopeRules.overlaps）→ 记录串行原因
🔑 重点：serialReasons 是波次级否决票——任一写组有串行原因，整波写操作退回串行（runMutatingGroups :507）。宁可慢，不冒险并行写重叠路径。
⚠️ 易错：指纹去重原则「宁漏勿误」——宁可不合并，也不错误合并。指纹精确匹配，描述稍有差异就判为不同步骤，可能重复执行，但绝不误删独立步骤。
并行模型与 worktree 隔离

读并行（runBatchParallel :1127）

  • Executors.newFixedThreadPool，线程名 mindcli-multi-agent
  • 每步独立缓冲，join 后按顺序 flush，避免输出交错（:1131-1182）

写并行（runMutatingBatchParallel :542）

  • 线程名 mindcli-multi-agent-worktree，并行度 min(leader, batchParallelism)
  • 每步独立 git worktree，forkForProject :299 fork registry

worktree 隔离四步

  • 基线快照 commitCheckpoint :555
  • 预创建 worktree create :574，任一失败 → 整波回退串行
  • 并行执行 fork registry
  • 合并 mergeWorktreeAndDispose :681，冲突 → FAILED 并报告（:686-690），绝不静默覆盖
⚠️ 易错：worktree 分支 registry 刻意不继承 MCP 工具（ToolRegistry.java:297）。MCP 可能有全局副作用，放隔离 worktree 会失控。
❓ 面试点：为什么用固定线程池，不用虚拟线程？
答：瓶颈在 LLM 网络 I/O，并发度被 profile 的 maxConcurrency 严格限制，固定线程池更可控；跨线程互斥由 ResourceLockManager（ReentrantReadWriteLock）兜底。
AgentPool 租借：最少权限优先
  • 每个 profile 持 Semaphore(maxConcurrency) 限流
  • preferredAgent 精确匹配 → 否则 role+工具过滤，按 privilegeScore 升序（最少权限优先）
  • tryAcquire 非阻塞扫候选，失败才阻塞——避免「假并行」
  • Lease 是 AutoCloseable :130，保证释放

06MCP 集成

MCP 服务器如何接入多代理工具链。

注册 → 过滤 → 调用 → 注入
  • 服务器 READY 后，每个工具注册为 mcp__{server}__{tool}（ToolRegistry :1099-1102）
  • 子代理经 toolDefinitionsForProfile :526 + AgentToolPolicy 过滤可见性
  • MCP 调用按 MCP_SERVER:<server> 做独占锁
  • externalContextSupplier = mcpServerManager::resourceIndexForPrompt 注入资源索引（:318）
⚠️ 易错：两处「MCP 不可用」——① worktree 分支不带 MCP 工具；② 自审 readOnly 过滤 mcp__*。别在需要 MCP 的步骤里指望这两阶段还能调 MCP。

08设计要点与安全防线

来自 docs/ 的关键决策 + 五层安全防线。

关键设计决策
🔑 TeamScheduler 抽取（2026-08-17）：从 1800 行编排器抽出纯函数调度层，只移决策、留下并发/执行。单一入口 nextWave，逐波增量语义。
🔑 WriteScopeRules 一致性：调度器和 ToolRegistry 共享同一套写域规则——「能否并行」和「路径是否允许」永不分歧。
⚠️ 自审 fail-closed：评审 JSON 解析失败一律不通过，最多重试 2 次。
五层安全防线
  • 1 规划 —— TEAM_PLANNER 提示约束
  • 2 权限 —— least-privilege 租借
  • 3 写域 —— WriteScopeRules 强制
  • 4 隔离 —— worktree 并行写
  • 5 自审 —— readOnly 复检

五层纵深防御：每一步假设上一层可能被绕过，层层设防，而非单点依赖。
