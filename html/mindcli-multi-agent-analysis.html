MindCLI /team 多智能体实现

结论：这是一个 master–slave 编排器架构——AgentOrchestrator 是主控，SubAgent 是执行从节点；调度决策被抽成纯函数 TeamScheduler；读任务用固定线程池并行，写任务用 git worktree 隔离并行、冲突即回退串行；全程靠最小权限 + 写范围判定 + 自审兜底。

DAG 任务图指纹去重worktree 写隔离最小权限池fail-closed 自审

1 · 核心组件

Master

AgentOrchestrator

规划 → 解析 → 主循环 → 自审重试 → 聚合。持有 SubAgent 从节点，内联调用 LLM 做规划（无独立 PLANNER）。

纯决策

TeamScheduler

唯一入口 nextWave(steps)，零依赖、无状态：就绪判定 → 去重 → 读写分区 → 串行原因 → 返回一波 ScheduleWave。

Worker

SubAgent

每个实例独立 profile + 历史，共享 LlmClient/ToolRegistry。跑 ReAct 工具循环 + 自审（review 强制 readOnly）。

资源池

AgentPool

按 profile 发 Semaphore(maxConcurrency) lease；先 tryAcquire 后阻塞回退；按 privilegeScore 升序选（最小权限优先）。

图结构

DependencyGraph

业务中立 DAG。readyNodes/blockedNodes，依赖状态语义由调用方注入（/team 与 /plan 分离）。

护栏

AgentBudget

循环退出：token 预算 + 停滞检测（3 轮相同工具签名）+ 硬迭代上限 50。

3 · 调度决策 nextWave

依赖就绪readyNodes：状态 PENDING 且依赖为 COMPLETED/SKIPPED 放行；FAILED 依赖阻塞下游。
指纹去重 collapseExecutableGroups按 stepFingerprint（类型|描述|工具|写范围|agent|风险|依赖）聚合，取 leader，重复项结果复制（宁漏勿误）。
读写分区readOnly 与 mutating 分开；mutating 判定在 TeamStepClassifier。
写范围重叠判定写范围为空或与它组重叠（WriteScopeRules.overlaps）→ 记录 serialReasons。
产出 ScheduleWaveserialReasons 是波级否决——任一写组有串行原因，整波写任务回退串行。

4 · 并行策略

读任务

固定线程池并行

mindcli-multi-agent，Executors.newFixedThreadPool(parallelism)；每步独立 ByteArrayOutputStream，join 后按步骤序 flush，避免终端输出交错。

写任务

git worktree 隔离并行

mindcli-multi-agent-worktree；commitCheckpoint 定基线 → 预建 worktree → forkForProject 派生 registry → 各写各的 → mergeWorktreeAndDispose 合并；冲突标记 FAILED 并报告文件，绝不静默覆盖。

无虚拟线程。跨线程工具互斥由 ToolDispatcher 静态 SHARED_LOCK_MANAGER + ResourceLockManager（ReentrantReadWriteLock，排序加锁）承担。
